# Johnnywrt maintenance instructions

**Before editing firmware, starting or rerunning a build, or publishing a release, read this entire file and `MAINTENANCE.md`, including its pre-build checklist and known test dependencies. Do not rely only on earlier chat context.** These notes make the build maintainable from a new computer or conversation; they do not replace the user's current request.

Check the latest failed Actions run before retrying. Record each confirmed failure cause and its necessary fix in `MAINTENANCE.md`; fix the cause and rerun the relevant checks. Never bypass a failing test just to publish an image.

After a failed build, do not start another full compilation after only a narrow unit-test fix. Reuse the saved original firmware artifact to reproduce the failure and pass the complete boot/function and old-to-new/new-to-new upgrade checks first. Use the same test entry points and transport as CI; SSH file-transfer previews do not validate serial-console input. Run the read-only diagnostic workflow on the saved artifact to check the actual CI environment before another release build. The user explicitly required this after three failed JohnnyWrt runs on 2026-10-28.

- The independent repository is `Johnnnypro/JohnnyWrt`, branch `main`. The original `ImmortalWrt-ImageBuilder/Johnny` branch is historical; keep its releases for recovery and the pinned previous-release upgrade fixture, but publish and check updates only in JohnnyWrt.
- Prefer the latest **stable** ImmortalWrt release and its matching kernel/modules. The user explicitly chose stable over snapshots on 2026-10-28. Check upstream again for future builds; never independently replace the kernel or falsify release metadata.
- Target x86/64, UEFI, SquashFS, 1024 MiB rootfs for compatibility with the current installation. Preserve partition layout for normal upgrades. Provide both a UEFI-capable fresh-install ISO and the EFI combined `.img.gz` usable for direct disk installation and LuCI sysupgrade.
- Include current signed **OpenWrt** MeowX packages and core from the vendor feed. Desktop/Android app version numbers are not OpenWrt package versions. Keep MeowX, ZeroTier, Aurora, offline dashboard and geodata. Use the independent JohnnyWrt homepage/network wizard and ZeroTier setup wizard; do not include iStore or the old QuickStart daemon/package. The user-requested `/usr/bin/quickstart` native console menu is separate; keep `/usr/sbin/quickstart` absent so historical daemon readiness detection stays correct.
- Preserve the native Dropbear `-z` SSH compatibility fix on fresh boots and retained-settings upgrades. Do not embed site-specific nftables rules or change password authentication, keys, ports, or listener bindings to solve this issue.
- Keep network, MeowX subscriptions and ZeroTier identity/configuration during retained-settings upgrades; verify in a disposable VM. No private site data, credentials, node URLs or keys in code, images, CI logs or releases.
- Run shell regression checks, existing QEMU smoke tests, actual SSH authentication, and retained-settings old-to-new plus new-to-new upgrade tests before publishing. Check the exact final artifact with `sysupgrade -T` on the intended router when access is authorized. That command validates only; it must not flash.
- Before rebooting or upgrading disposable guests, wait for `/overlay/.fs_state` to be `2` as well as successful SSH authentication, then sync. An early SSH login does not mean first-boot initialization has completed; an unready overlay may be cleared on the next boot.
- The previous-release upgrade fixture uses QuickStart's DHCP-client LAN; apply the helper-port readiness condition only while its binary exists. New firmware must have live LAN and no pending network changes. Before recording its retention baseline, also wait for the committed `dheth0` bridge port and no pending network changes. Compare files against that same baseline immediately before each flash as well as afterward; never refresh it to hide background changes. See the no-flash reproduction and historical-evidence limits in `MAINTENANCE.md`.
- Retain previous releases for recovery. Publish checksums, package manifest, source revision and clear fresh-install versus upgrade instructions. Do not claim arbitrary future major-version compatibility.
- Keep the LuCI online updater fixed to this repository. Accept only stable 25.12-series EFI SquashFS images with matching root partition size; verify SHA256 and sysupgrade -T before allowing an explicitly confirmed, configuration-preserving flash. Do not accept arbitrary URLs or enable automatic unattended flashing.
- Building/releasing an image does not authorize flashing a running router. Obtain explicit flashing instructions before interrupting it.
- Keep changes surgical and record results and any remaining limitations in `MAINTENANCE.md` / release notes.
- Keep the user-requested UI layout: updater inside System → Backup / Flash Firmware, ZeroTier immediately below MeowX under Services, and no empty VPN category. Fresh installs use hostname `JohnnyWrt`; retained-settings upgrades preserve custom names. Run the UI layout/component checks and adapt guarded patches when upstream LuCI changes.
